# MAPS / AeroMesh — Implementation Plan

**Goal.** A generator that takes any set of closed curves and returns a
*certified* block topology, then a RANS-ready structured mesh — end to end, no
network, no manual steps, and no rule specific to any geometry.

**Guiding principle.** Build the physics-free path completely first. It is
self-contained, needs no training, and is the verification baseline for anything
that comes later.

**Second guiding principle, added after the first iteration.** Nothing is
prescribed. If a stage cannot decide something from the geometry, the answer is
to give it the information it is missing — not to supply a template. The
hardcoded blocking that ended the first iteration was not a shortcut taken out of
laziness: the topology stage had only node degree to work with, and a template
was the only reachable output.

Live status, gates and the decision log: [PROJECT_TRACKER.md](PROJECT_TRACKER.md).

---

## Build order

```
S0  Foundation + data model   -> a Region from any set of loops        [done]
S1  Medial engine             -> both skeletons, all fields            <- foundation
S2  Singularity solver        -> positions, types, certificates
S3  Decomposition             -> a certified block graph
S4  Mesh construction         -> coordinates from a block graph
S5  Adversarial gate          -> proof that nothing is prescribed
S6  Quality + optimisation    -> closes the loop
S7  Bunin phi-field (FEM)     -> optional refinement
```

Three ordering decisions worth stating.

- **S0 before everything.** If the loop-set data model is not in place before the
  medial engine is written, every stage after it acquires a single-body
  assumption that has to be unpicked when the flap arrives.
- **S1 before S2 before S3.** The first iteration inverted this and produced a
  template. A decomposition stage with no singularity solver behind it has
  nothing to decompose against.
- **S5 before S6.** The invariant gates are what stop the next false-confidence
  build. Optimising a mesh whose topology is unverified optimises noise.

## S0 — Foundation and data model (1 week) — *done 2026-09-08*

**Delivered:** `Loop`, scale-invariant corner detection, cusp opening, `Region`,
far-field generation, the AeroShape intake, 126 invariant tests, one example.

Points worth carrying forward:

- **Corner detection extrapolates total turning, not a chord angle.** For a
  smooth arc, turning is exactly linear in the window width, so the
  extrapolation to zero width is exact. A chord-angle measure saturates at high
  curvature and reports a NACA leading edge as a corner.
- **Resampling preserves corners.** Uniform arc-length sampling of a polygon
  chamfers every corner and silently shrinks a far-field box.
- **Cusps are opened perpendicular to their own axis.** An equal-arc-offset cut
  gives an asymmetric face, and the asymmetry changes the corner angle and hence
  the derived element count — 105°/59° instead of 82°/82°, n_c of 3 and 2
  instead of 3 and 3.

**Gate — met.** Seven configurations, one call, no branch on body type or count.

## S1 — Medial engine (2 weeks) — *the foundation*

Replaces `medial/` outright.

**1.1 Membership.** A Voronoi ridge is medial when its generators lie on
different loops, or far apart on the same one. Drop the CDT from this path — it
is currently computed and discarded, and `triangle` is a dependency doing no
work. Voronoi over CDT circumcentres was the right call; keep it.

**1.2 Fields.** On every medial point: r_m, θ_m, n̂₁, n̂₂, the two touch points,
and arc length s. θ_m is the quantity every later stage consumes; without it
there is no automatic topology.

**1.3 Pruning.** On θ_m, not arc length. A branch generated by boundary noise
subtends a near-flat angle; a real one does not. Since θ_m must be computed
anyway, this costs nothing.

**1.4 Typing.** N / C / D, with corners taken from S0 rather than re-derived,
and flares extended to r_m = 0 at the corner point.

**1.5 Finite contact.** An exact circle returns an empty graph otherwise. Detect
it, equivalence the arc to an elliptical one, assign k = −⌊max θ_m/(π/2)⌋.

**1.6 Two entry points.** `interior_axis(loop)` per body and
`exterior_axis(region)`.

**Risk to watch.** Robustness at high-curvature noses and in thin slots. Budget
explicit cases for thin sections and for a two-element gap.

**Gate.** r_m within 1% of analytic for an annulus and an ellipse; no
zero-radius branches; **b₁ = h** for one, two and three bodies; a circular body
returns a finite-contact vertex.

## S2 — Singularity solver and certificates (1.5 weeks)

**2.1** n_opt = round((π − θ_m)/(π/2)) along every medial edge.

**2.2** Flux balance at Fogg\'s three critical position classes only — θ_m
crossings of π/4 and 3π/4, medial vertices, concave-corner switch points. The
naive version samples the whole axis; only these positions can carry an
imbalance.

**2.3** k = −⌊max θ_m/(π/2)⌋ at finite contact; n_c at corners from the fluid
interior angle, which S0 already computes.

**2.4** Merge within a local [r_m/4, r_m], cancelling ± pairs. Local, so mixed
scales in one domain each get their own tolerance.

**2.5** Both certificates: b₁ = h, and Σkᵢ against χ = 1 − h.

**Gate.** A lone airfoil and a lone fuselage return zero singularities; a cusped
configuration returns LE and TE singularities and nothing else; a two-element
case returns singularities inside the slot; the budget balances every time.

## S3 — Decomposition (2.5 weeks)

Replaces `blocking/`. The hardest stage, and the one that must contain no
per-case code.

- Fogg\'s neighbour database: for each singularity, explore the axis in every
  direction and record what it meets — another singularity, a convex corner, a
  concave-corner split — with a resolved/unresolved flag.
- Ranked split search: candidates are medial radii (constant-s) and ρ-level sets,
  n = 0 preferred over n = 1, medial angles nearer π and π/2 favoured within
  each. A singularity is fixed into a block corner only when no split exists.
- Midpoint-subdivision templates for logically convex m-gons — the one permitted
  primitive, and it must be named as such in the code.
- Emit a block graph with conformal connectivity; solve the edge-division
  integer programme.

**Gate.** Lone airfoil → ring; cusped TE → the classic C topology; box far field
→ ring plus corner blocks; two-element → slot blocks. All from one code path,
and a grep of `blocking/` for any body or domain name returns nothing.

## S4 — Mesh construction (1.5 weeks)

Transfinite interpolation per block; Thompson–Thames–Mastin elliptic smoothing
with wall spacing as a boundary condition; tanh clustering from Δy₁, r, N_wall;
export through `meshio`. Both algorithms are classical, roughly 50 and 200 lines,
and both references are in `PAPER/references`. Write no file writers.

**Gate.** SU2 opens the mesh; the minimum cell Jacobian is positive everywhere.

---

## S5 — Adversarial geometry gate (1 week)

What makes *nothing is prescribed* checkable rather than asserted.

- **Metamorphic.** Rotate, scale, translate, mirror → the block graph must come
  back isomorphic. A template cannot pass this.
- **Randomised.** Random CST sections at random positions inside random convex
  outer loops → a certified blocking every time. Anything hardcoded breaks on
  the first unfamiliar shape.
- **Per-module invariants.** r_m against an analytic annulus, θ_m against an
  analytic wedge, b₁ = h, positive block areas, conformal shared edges, every
  boundary arc covered exactly once.

**Gate.** A thousand randomised configurations give a thousand certified block
graphs; every metamorphic pair is isomorphic.

---

## S6 — Quality and optimisation (1.5 weeks)

Exact metrics — wall orthogonality, minimum Jacobian, boundary-layer aspect
ratio, metric jump across interfaces, achieved y⁺ — cross-checked against
`vtkMeshQuality`. Δy₁ bounded by y⁺, Re and altitude:

$$\\Delta y_1 = \\frac{y^+ \\nu(z)}{u_\\tau}, \\quad u_\\tau = U_\\infty\\sqrt{C_f/2}, \\quad C_f \\approx 0.026\\,\\mathrm{Re}^{-1/7}$$

L-BFGS over the continuous parameters (ρ*, Δy₁, r, N_wall). CMA-ES only if the
landscape proves multimodal — the certificates make that less likely, since the
topology is no longer part of the search.

**Gate.** F(x*) beats a sensible hand-set default, measurably.

---

## S7 — Bunin φ-field, optional (1 week)

Direct FEM solve of ∇²φ = Σ kᵢ(π/2)δ(r − pᵢ) with the clustering and far-field
boundary conditions, used to let singularities float inside their polygons and
equalise element size — the refinement Fogg explicitly leaves open.

**Not** a neural operator. See D5: the operator existed to make a thousand
CMA-ES quality evaluations cheap, and that search no longer exists.

## What to resist

- **Do not supply a template when a stage cannot decide.** Give it the missing
  information instead. That is the whole lesson of the first iteration.
- **Do not special-case a body count or a body type.** If a change needs to know
  whether there are one or three bodies, the data model is being worked around.
- **Do not reintroduce a domain-type switch.** The far field is a curve. What
  topology it produces is derived.
- **Do not start the surrogate.** It has no data generator until S6 and no
  problem to solve after S2.
- **Do not skip S5.** Thirty-four passing shape assertions are how a skeleton
  with zero-radius branches shipped as *strictly validated*.
